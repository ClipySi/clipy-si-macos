# ClipySi for macOS

**English** · [日本語](README_ja.md)

**ClipySi is a privacy-first clipboard manager.**

ClipySi stores copied content as searchable history and lets you quickly paste previous items or saved snippets.
The macOS version is an independent rewrite inspired by the feel of [Clipy](https://github.com/Clipy/Clipy).
It is not affiliated with or endorsed by the Clipy Project.
The app is named **ClipySi** so it does not reuse the `Clipy` / `ClipMenu` product names.

## Download

[ClipySi 1.0.0 is available from GitHub Releases.](https://github.com/ClipySi/clipy-si-macos/releases/latest)

The distribution build is Developer ID signed and notarized.
It is a universal build for both Apple Silicon and Intel Macs, and runs on macOS 14 Sonoma or later.
Automatic updates are supported through Sparkle 2.

## Features

### Clipboard History

- Monitors the pasteboard and stores copied content as searchable history.
- Supports text, RTF, RTFD, PDF, filenames, URLs, TIFF, and other pasteboard representations.
- Detects duplicates and moves a copied-again item back to the top.
- Supports history count limits, automatic trimming, and on-disk blob garbage collection.
- Includes excluded-app settings so copies from selected apps are not stored.
- Can optionally import screenshots saved to the Desktop.

### Menu And Paste

- Provides access to history, snippets, and settings from a menu-bar status item.
- Opens the history panel at the cursor position with a global hotkey.
- Assigns `⌘0`-`⌘9` number-key shortcuts to the first history items.
- Pastes into the frontmost app by injecting `⌘V` with `CGEvent`.
- Supports modifier actions for plain-text paste, delete from history, and paste then delete.

### Snippets

- Manages folders and snippets for quick paste from the menu.
- Provides a three-pane SwiftUI editor for create, edit, delete, reorder, and move-to-folder workflows.
- Supports import and export compatible with the original Clipy snippet XML format.

### System Integration

- Supports launch at login through `SMAppService`.
- Supports update checks through Sparkle 2 with EdDSA-signed appcasts.
- Settings cover general behavior, menu, stored types, excluded apps, shortcuts, and privacy.

## Security And Privacy

A clipboard manager handles what users copy, including passwords and tokens.
ClipySi treats that as a security-sensitive design constraint and protects content before storage, at rest, and at display time.

- Checks pasteboard privacy markers such as `TransientType`, `ConcealedType`, and `AutoGeneratedType` before reading content.
- Does not store clips that carry privacy markers.
- Stores history payloads and thumbnails encrypted with AES-GCM.
- Stores encryption keys in the Keychain with the `ThisDeviceOnly` attribute.
- Uses HMAC-SHA256 keyed by the Keychain key for duplicate detection.
- Detects passwords, API keys, tokens, and similar secrets on device and masks them when displayed.
- Secret masking is display-only, so the actual pasted content is not changed.
- Can optionally require Touch ID or password confirmation before pasting a masked item.
- Diagnostics are opt-in and off by default.
- Clipboard contents are not sent automatically.
- Paste requires the macOS Accessibility permission.
- Input Monitoring is not requested.

The shared Rust core `clipy-si-core` is maintained in a separate repository and is not included in this public repository.
The released app links it as a prebuilt, statically-linked binary.
Secret masking, cryptography, record/vault formats, and sync decisions are implemented in that core.

For details, see the [Privacy Policy](docs/PRIVACY.md), [Distribution Matrix](docs/DISTRIBUTION.md), and [Security Policy](SECURITY.md).
Implementation security requirements are documented in [security-guidance.md](security-guidance.md).

## Building From Source

For normal use, install the signed and notarized release build from GitHub Releases.

The app links the shared Rust core (`ClipySiCore`) as a prebuilt, statically-linked
binary distributed with releases. Xcode resolves it as a Swift package dependency, so
building the app does **not** require the core's source. The core is developed in a
separate repository; you only need it if you are changing the core itself.

Clone and open the project.

```bash
git clone https://github.com/ClipySi/clipy-si-macos.git
cd clipy-si-macos
```

Make sure full Xcode is selected.

```bash
xcode-select -p
# If this does not point to /Applications/Xcode.app/Contents/Developer:
# sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

Debug build:

```bash
set -o pipefail && xcodebuild \
  -project Clipy.xcodeproj \
  -scheme Clipy \
  -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -skipMacroValidation \
  CODE_SIGNING_ALLOWED=NO \
  build 2>&1 | xcbeautify
```

Tests:

```bash
set -o pipefail && xcodebuild \
  -project Clipy.xcodeproj \
  -scheme Clipy \
  -destination 'platform=macOS,arch=arm64' \
  -skipMacroValidation \
  -testLanguage en -testRegion US \
  CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO \
  test 2>&1 | xcbeautify
```

Lint:

```bash
swiftlint lint --quiet
swiftlint --fix
```

`-skipMacroValidation` is required for every `xcodebuild` CLI invocation.
Tests should be pinned to English with `-testLanguage en -testRegion US`.
Local ad-hoc signed builds may cause macOS to ask for Accessibility permission again after each rebuild.

## Architecture

ClipySi uses the SwiftUI app lifecycle while AppKit manages macOS-specific behavior such as the menu bar, global hotkeys, pasteboard monitoring, and paste injection.

The `AppDelegate` under `@NSApplicationDelegateAdaptor` owns the `NSStatusItem`, non-activating `NSPanel`, pasteboard polling, `CGEvent` paste, login item integration, and Sparkle updater.
History and snippets are shown in a unified floating panel that opens at the cursor position.

Persistence uses SQLiteData / GRDB.
The database stores metadata, while clip bodies and thumbnails are stored on disk as encrypted blobs.
Writes are routed through repositories, and SwiftUI reads live queries through `@FetchAll`.

Concurrency assumes Swift 6 strict concurrency.
AppKit, menu, paste, and hotkey behavior are kept on `@MainActor`, and value types that cross domains are treated as `Sendable`.

See [DESIGN.md](DESIGN.md) for design details.

## Tech Stack

| Concern | Choice |
| --- | --- |
| UI | SwiftUI + AppKit |
| Persistence | SQLiteData / GRDB / swift-structured-queries |
| Dependency injection | swift-dependencies / swift-sharing |
| Hotkeys | Magnet / Sauce / KeyHolder |
| Screenshot monitoring | Screeen |
| Snippet XML | AEXML |
| Cryptography | CryptoKit / Keychain / Rust core |
| Login item | SMAppService |
| Automatic updates | Sparkle 2 |

ClipySi does not use Realm, RxSwift, PINCache, XIB, `NSCoding`, or LoginServiceKit from the original Clipy codebase.

## Contributing

Issues and pull requests are welcome.

The app links a prebuilt ClipySiCore binary, so building it does not require the core's source.
Public CI runs SwiftLint and the redaction/logging gate; the full macOS build and test suite runs in the maintainer environment.

Before opening a PR, run `swiftlint lint --quiet` and the test suite if possible.
Security-sensitive changes should be checked against [security-guidance.md](security-guidance.md).
If you find a vulnerability, please report it privately through the process in [SECURITY.md](SECURITY.md) instead of opening a public issue.
